# Counselor caseload

Staff open **Counselor caseload** from Admissions navigation. The default view lists work needing attention, ordered by overdue work, approaching deadlines, verification needs, counselor review and other incomplete work. Each student/college group includes the assigned counselor(s), deadline (including estimated or missing dates), application status and direct next-action links. General essays and unmatched applications remain visible.

Filters combine student-name search, assigned counselor, graduation year, college and attention category. They are retained in the URL, with filtering before pagination (25 work groups). All work includes groups with no current flags; this is not a readiness certification. Date-only deadlines and tasks use the firm's calendar day; timed task deadlines are compared as instants. Submitted, under-review, decided and withdrawn applications do not receive pre-submission deadline/prompt/checklist warnings. Still-open essay reviews and linked tasks remain visible. Only verified current-year published requirements generate required-response gaps, using the same canonical prompt-slot identity as the planning board. Firm-published revisions take precedence.

The view reads existing data and links to existing workspaces. It creates no tasks or reminders and changes no assignments, sharing or source content. Owners, admins and read-only staff retain their existing firm-wide read access; counselors, essay coaches and tutors see assigned students only. Counselor filters narrow this authorized set. Students and parents are redirected to their own portals and cannot read the caseload query. Existing action permissions remain enforced at each destination. Archived students are excluded.

Queries use `getDb()` with explicit firm/student filters and fetch compact metadata in ordered pages and batches. Essay bodies, feedback, interview answers, stories and strategy notes are not fetched. Read errors fail explicitly rather than pretending no work exists. Assignment lookup also reads every page and fails on query errors. No schema migration, new service-role client, dependency, environment variable or background job is needed.

Acceptance covers combined filters, specific next-action links, mobile accessibility, assignment revocation, owner visibility, tenant isolation and denial for student/both parents. Unit tests exercise dates, closed applications, general work, workflow task ownership, prompt versions/coverage, filter combinations and pagination. See the PR for final test results. Deployment requires separate authorization.
