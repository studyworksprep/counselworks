# Saved-version essay coaching

Students and assigned counseling staff open **Saved-version coaching** in the existing connected writing workspace. Choose one of the saved versions already available in version comparison, then **Review version and context**. Preview the exact saved body, assigned prompt and limits. Autosaved working text, later saves and other versions are separate and are never substituted for the chosen draft.

Select current student interview answers, confirmed stories/narratives, reviewed shared strategy, or student follow-up replies. Only checked sources, the chosen saved body and the displayed prompt are sent to the established provider. Parent interviews, private counselor notes, other drafts and unselected context are excluded. At least one source is required. Limits are 20 sources, 30,000 source characters, a 50,000-character saved draft and a 12,000-character prompt; over-limit requests are refused rather than truncated. Coaching, interview assistance and essay planning share the existing 10/hour and 40/day allowance.

Guidance contains observations, questions, evidence gaps and source citations. A passage quotation must appear exactly once in the chosen saved version; a whole-draft observation uses no quotation. Unsupported quotations, ambiguous passages and invented source keys are refused. Guidance prohibits rewritten prose, hooks, theses, dialogue, invented experiences, college facts and admissions predictions. The student chooses the experience, interpretation and wording.

Suggestions are private to their requester. **Review and edit feedback** opens one editable comment at a time. **Add reviewed feedback** explicitly adds that edited comment to the existing student/counseling-team thread, retaining the exact version number and quotation and every selected input reference, including inputs not cited in the model's answer. Concurrent publication of the same suggestion saves once. Refused saves keep the edited text, and dirty reviews require saving or explicit discard before the version or sources can change.

Counselors can use the existing comment controls to create a student-owned revision task, with the original comment, quote and saved version. Task completion, resolving feedback, submitting writing and counselor approval remain independent actions. Coaching never writes the essay body, creates a saved essay version, changes approval/submission, or expands essay sharing. Parents continue to see only the current family-shared writing and independently shared plans/outlines; feedback, coaching requests, revision instructions and saved-version history stay private to the student and counseling team.

Source revisions, assigned-prompt changes, lost assignment and source withdrawal invalidate private results and block stale publication, including changes during a provider call. Saving a later draft leaves an unchanged earlier chosen version valid. Published comments remain historical feedback on their original version; source revisions are marked rather than silently swapped. A review flag on the student's own story retains their working discussion, while actual source-access withdrawal hides derived student feedback and linked revision work. New revision assignments require current eligible sources. Database policies and the query/authorization layer both enforce these rules, including task lists, totals and direct task actions in the local service fallback.

Earlier unversioned counselor reviews remain readable and clearly labeled. New review generation uses the saved-version workflow; the older current-body generation action is removed. No existing review is relabeled as a version-linked result.

## Implementation and release

Migration **00068_saved_version_essay_coaching.sql** adds private requests, a content-free quota ledger, immutable feedback provenance and guarded invoker functions. Saved snapshots become append-only for ordinary accounts; existing saves insert new versions and whole-essay deletion retains its cascading behavior when no revision work blocks it. Both new tenant tables have RLS; public/anonymous access is revoked. It reuses the existing provider, credentials, source catalog, feedback and revision tasks. No new privileged client, dependency, background job, email or automatic backfill is introduced.

Migration 68 and application rollout are pending separate release authorization. Apply the reviewed migration before deploying the matching application. Production migration 67 and PR #71 are already released; this upgrade does not change their migration files.

Validation covers exact Unicode/ambiguous quotations, selected-only provider payloads, actor/version/source boundaries, quota failure, in-flight changes, reviewed comment promotion, tenant and parent isolation, source withdrawal, shared quotas and concurrent publication. The browser journeys exercise the real local app/database/authentication with a loopback fixture at the provider SDK boundary, including counselor, student, both parents, revision tasks, phone layout and accessibility. They do not evaluate the quality or availability of the live model.
